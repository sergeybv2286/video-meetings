# PRD: Загрузка файла встречи

**Дата**: 2026-10-08
**Статус** Draft

## Цель

Дать пользователю возможность прикрепить к своей встрече файл (видео, аудио, транскрипт или документ), сохранить его на сервере и видеть его на странице встречи. Это основа для последующей обработки файлов (транскрибация и т.п.), которая делается отдельной фичей.

## Пользовательские сценарии

- Пользователь открывает свою встречу без файла -> видит блок загрузки с подсказкой о допустимых форматах и размере
- Пользователь выбирает файл (через диалог или перетаскиванием) -> файл загружается, виден прогресс
- Пользователь загрузил допустимый файл -> в карточке встречи отображаются имя, тип, размер, дата загрузки и статус «Загружен»
- Пользователь выбирает файл недопустимого типа или больше 500 МБ -> получает понятное сообщение об ошибке на русском, загрузка не начинается
- Загрузка прервалась (обрыв сети, ошибка сервера) -> пользователь видит сообщение об ошибке и может повторить загрузку; в карточке нет «битого» файла
- Пользователь открывает встречу с файлом -> видит информацию о файле и может скачать его
- Пользователь хочет заменить файл -> загружает новый, старый удаляется
- Пользователь удаляет файл -> файл исчезает из встречи и с сервера, блок загрузки снова доступен
- Пользователь пытается загрузить файл в чужую встречу или несуществующую -> получает 404

## В скоупе

- Загрузка одного файла на встречу, максимум 500 МБ.
- Допустимые форматы:
  - видео: mp4, webm, mov;
  - аудио: mp3, m4a, wav;
  - текст: txt, vtt, srt;
  - документы: pdf, docx, pptx.
- Проверка типа и размера на клиенте (для быстрой обратной связи) и на сервере (обязательно).
- Хранение самих файлов в локальной файловой системе сервера.
- Хранение метаданных файла: исходное имя, тип, размер, дата загрузки, статус, привязка к встрече.
- Статус файла как подготовка к обработке: «Загружен» (на этой итерации других статусов обработки нет, но модель статуса должна допускать их добавление).
- Эндпоинты API: загрузка файла встречи, получение информации о файле, скачивание, удаление, замена. Доступ только владельцу встречи.
- Интерфейс на странице встречи: зона загрузки (выбор и drag-and-drop), прогресс, карточка файла, скачивание, замена, удаление с подтверждением.
- Отображение наличия файла в списке встреч (индикатор «есть файл»).
- Сообщения интерфейса и ошибок API — на русском.
- Обновление документации (`CLAUDE.md`, `README.md`, `.env.example` при новых переменных).

## Не в скоупе

- Сама обработка файла: транскрибация, резюме, извлечение текста, генерация превью.
- Несколько файлов на встречу.
- Встроенный видео/аудио-плеер и просмотр документов в браузере (только скачивание).
- Докачка и многочастная (chunked) загрузка больших файлов.
- Антивирусная проверка.
- S3-совместимое и другое облачное хранилище.
- Шеринг файла другим пользователям, публичные ссылки.
- Квоты на пользователя, шифрование файлов на диске.
- Перенос хранения встреч из памяти в БД (отдельная задача).

## Технические ограничения

- Встречи сейчас хранятся в памяти API и теряются при перезапуске, а файлы и метаданные должны переживать перезапуск. Нужно не допустить «осиротевших» файлов и метаданных, ссылающихся на пропавшую встречу, либо решить это отдельно до/вместе с фичей.
- Максимальный размер файла — 500 МБ; лимит должен соблюдаться на сервере независимо от клиента, включая лимит размера тела запроса и таймауты на web и api.
- Файлы лежат на локальном диске сервера: путь хранения настраивается через переменную окружения; папка с файлами не коммитится в git (`.gitignore`), переменная добавляется в `.env.example`.
- Тип файла проверяется на сервере не только по расширению, но и по содержимому/MIME; исходное имя файла не должно влиять на путь сохранения (защита от path traversal).
- Загрузка не должна читать весь файл в память целиком.
- Все эндпоинты защищены JWT; доступ только к файлам своих встреч.
- Web (порт 3000) и API (порт 3001) — разные origin, CORS и клиентская загрузка должны это учитывать.
- Язык интерфейса и сообщений об ошибках — русский.

## Критерии готовности

- [x] Владелец встречи может загрузить файл допустимого формата размером до 500 МБ, и он отображается на странице встречи с именем, типом, размером, датой и статусом «Загружен»
- [x] Файл размером более 500 МБ отклоняется и на клиенте, и на сервере с сообщением на русском
- [x] Файл недопустимого типа отклоняется на сервере, даже если переименовано расширение (проверка по содержимому/MIME)
- [x] Во время загрузки отображается прогресс; при ошибке показывается сообщение, а частично загруженный файл не остаётся ни на диске, ни в метаданных
- [x] Загруженный файл можно скачать, содержимое совпадает с исходным (совпадает контрольная сумма)
- [x] Загрузка нового файла в встречу с файлом заменяет старый: на диске и в метаданных остаётся только новый
- [x] Удаление файла (с подтверждением) удаляет его с диска и из метаданных
- [ ] Метаданные и файлы сохраняются после перезапуска API — **не выполняется как сформулировано**: встречи хранятся в памяти (вне скоупа PRD), поэтому после перезапуска встреча пропадает, и файл без встречи недоступен. Вместо сохранения реализована очистка: при старте API удаляет записи и файлы без встречи (фаза 4), чтобы не копились «осиротевшие» данные (см. «Технические ограничения»). Критерий станет выполнимым после переноса встреч в БД; очистку тогда нужно пересмотреть
- [x] Запросы к файлу чужой или несуществующей встречи возвращают 404; запросы без JWT — 401
- [x] В списке встреч видно, у каких встреч есть файл
- [x] Интерфейс корректно работает на мобильной ширине и поддерживает загрузку с клавиатуры (доступность)
- [x] Для API-эндпоинтов есть unit- и e2e-тесты: успешная загрузка, лимит размера, недопустимый тип, чужая встреча, замена, удаление, скачивание
- [x] `pnpm format`, `pnpm lint`, `pnpm typecheck`, `pnpm test` и `pnpm --filter api test:e2e` проходят
- [x] `CLAUDE.md` (корневой и в `apps/*`), `README.md` и `.env.example` обновлены в соответствии с изменениями
