# Plan: Транскрибация файла встречи через локальный Whisper

**PRD:** docs/prd-meeting-file-transcription.md
**Дата:** 2026-10-29

## Фазы реализации

### Фаза 1: Tracer Bullet — MP3/MP4 → очередь → Whisper → «Готово»

**Цель:** Минимальный сквозной путь на API: после загрузки MP3/MP4 создаётся задача, последовательная очередь прогоняет её через локальный Whisper `base`, статус и результат сохраняются в БД и видны в `GET /meetings/:id/file`.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Prisma: модель транскрибации, привязанная к `MeetingFile` (статус «В очереди»/«В процессе»/«Готово»/«Ошибка», текст, время завершения, текст ошибки, каскадное удаление), миграция через `db:migrate`; поле `status = UPLOADED` у файла не меняется
- [ ] Определение MP4/MP3 по содержимому (как в валидации загрузки) и создание задачи после успешных `POST` и `PUT /meetings/:id/file`; для других форматов задача не создаётся
- [ ] `TranscriptionRunner`: запуск Whisper `base` (автоопределение языка) и `ffmpeg` во внешнем процессе, без блокировки Node и без внешних сетевых вызовов; пути/команды — через переменные окружения (`.env.example`)
- [ ] Последовательная очередь в процессе API (один файл за раз, порядок загрузки), смена статусов «В очереди» → «В процессе» → «Готово» с записью текста и времени завершения
- [ ] Статус транскрибации в ответе `GET /meetings/:id/file`; тесты: unit (очередь, смена статусов, порядок и единственность «В процессе») и e2e (MP3/MP4 → «В очереди» и далее, PDF → без транскрибации), Whisper подменён

**Когда готова:** После загрузки тестового MP3 и MP4 (Whisper подменён) `GET /meetings/:id/file` показывает статус, доходящий до «Готово», с непустым текстом в БД; для PDF транскрибации нет; одновременно в работе не больше одного файла; unit и e2e тесты проходят.

### Фаза 2: Надёжность — ошибки, таймаут, перезапуск, удаление, замена файла

**Цель:** Очередь корректно переживает сбои и изменения файла: ошибки не роняют API, зависшие задачи прерываются, задачи восстанавливаются после рестарта, результаты не «протекают» между файлами.
**Затрагивает:** backend
**Задачи:**

- [ ] Обработка ошибок: повреждённый файл, недоступные Whisper/ffmpeg → статус «Ошибка» с русским сообщением, API не падает; максимальный срок обработки (env) — по истечении процесс убивается, статус «Ошибка»
- [ ] Восстановление при старте: задачи «В очереди» и «В процессе» ставятся в очередь заново после `MeetingFilesCleanupService`, задачи удалённых файлов не запускаются
- [ ] Каскадная отмена: удаление файла или встречи прерывает идущий процесс, удаляет запись транскрибации, результат не записывается
- [ ] Замена файла (`PUT`): прежний результат сбрасывается, для MP4/MP3 стартует новая задача, для остальных форматов (PDF) статуса нет; результат старой задачи, завершившейся позже, игнорируется
- [ ] Тесты: unit (ошибки, таймаут, отмена, защита от устаревшего результата) и e2e (повреждённый файл, перезапуск с восстановлением, удаление файла/встречи, замена на MP3/MP4 и на PDF)

**Когда готова:** Падение Whisper и таймаут дают «Ошибка» с русским текстом без падения API; после рестарта незавершённые задачи выполняются, задачи удалённых файлов — нет; удаление и замена файла не оставляют чужих результатов; тесты проходят.

### Фаза 3: API текста, скачивания `.txt` и повторного запуска

**Цель:** Владелец встречи может получить текст транскрибации, скачать его и перезапустить упавшую задачу.
**Затрагивает:** backend
**Задачи:**

- [ ] `GET /meetings/:id/file/transcription` — статус и текст; `JwtAuthGuard` + `MeetingOwnerGuard` (чужая или несуществующая встреча — 404, без токена — 401)
- [ ] Скачивание `.txt`: UTF-8, `Content-Disposition: attachment`, имя на основе имени исходного файла
- [ ] `POST /meetings/:id/file/transcription/retry`: для «Ошибка» ставит задачу в очередь заново, для остальных статусов — 409; действующий `RATE_LIMIT` распространяется на новые эндпоинты, повтор ограничивается дополнительно
- [ ] Тесты: e2e (права доступа 401/404, содержимое и заголовки `.txt`, retry 200/409, лимит запросов) и unit
- [ ] Документация: `apps/api/CLAUDE.md`, корневой `CLAUDE.md` и `README.md` — новые эндпоинты, переменные окружения, установка Whisper и ffmpeg

**Когда готова:** Все три эндпоинта работают по критериям PRD, доступны только владельцу, `.txt` скачивается корректно, retry возвращает 409 вне статуса «Ошибка»; документация API обновлена; тесты проходят.

### Фаза 4: Веб-интерфейс на странице встречи

**Цель:** Пользователь видит статус транскрибации рядом с файлом без перезагрузки страницы, читает текст, скачивает `.txt` и повторяет упавшую задачу.
**Затрагивает:** frontend
**Задачи:**

- [ ] Функции в `apps/web/src/lib/api.ts`: получение статуса и текста, скачивание `.txt`, повторный запуск (ошибки на русском)
- [ ] Компонент транскрибации под файлом: бейдж статуса («В очереди», «В процессе», «Готово», «Ошибка»), текст при «Готово», сообщение об ошибке и кнопка «Повторить», кнопка «Скачать .txt»; для не-MP4/MP3 статус не показывается
- [ ] Периодический опрос API, пока есть задача «В очереди»/«В процессе»; остановка опроса, когда задач в работе нет; сброс состояния при замене/удалении файла
- [ ] Подключение компонента на страницу встречи
- [ ] Unit-тесты веб-компонентов (все статусы, опрос и его остановка, скачивание, повтор, отсутствие статуса для PDF) и обновление `apps/web/CLAUDE.md`, `README.md`

**Когда готова:** После загрузки MP3/MP4 на странице встречи статус сам меняется до «Готово» или «Ошибка», работают «Скачать .txt» и «Повторить», все надписи на русском; `pnpm lint`, `pnpm typecheck` и `pnpm test` проходят; документация обновлена.
