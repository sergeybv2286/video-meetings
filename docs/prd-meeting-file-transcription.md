# PRD: Транскрибация файла встречи через локальный Whisper

**Дата**: 2026-10-28
**Статус** Draft

## Цель

После загрузки MP4 или MP3 файла во встречу система автоматически превращает речь в текст локальной моделью Whisper `base`. Пользователь видит статус транскрибации и, когда она готова, может прочитать текст и скачать его. Данные не уходят во внешние сервисы.

## Пользовательские сценарии

- Пользователь загружает MP4 или MP3 во встречу -> файл сохраняется, транскрибация ставится в очередь, рядом с файлом виден статус «В очереди».
- Пользователь остаётся на странице встречи -> статус сам меняется «В очереди» -> «В процессе» -> «Готово», обновлять страницу не нужно.
- Транскрибация завершена -> под файлом виден текст, есть кнопка «Скачать .txt».
- Транскрибация упала -> виден статус «Ошибка» с понятным сообщением на русском и кнопка «Повторить».
- Пользователь нажимает «Повторить» -> статус снова «В очереди», задача запускается заново.
- Пользователь заменяет файл (PUT) на другой MP4/MP3 -> прежний результат удаляется, транскрибация нового файла стартует заново.
- Пользователь заменяет файл на формат, который не транскрибируется (например, PDF) -> прежний результат удаляется, статуса транскрибации нет.
- Пользователь удаляет файл или встречу -> задача отменяется, текст удаляется вместе с файлом.
- Пользователь загружает во встречу PDF, DOCX и другие форматы, кроме MP4 и MP3 -> файл загружается как раньше, транскрибация не запускается и статус не показывается.
- Несколько файлов разных пользователей загружены подряд -> обрабатываются по одному в порядке загрузки, остальные ждут в статусе «В очереди».
- API перезапущен во время транскрибации -> после старта задачи со статусами «В очереди» и «В процессе» запускаются заново.

## В скоупе

- Автоматический запуск транскрибации после успешной загрузки (`POST` и `PUT /meetings/:id/file`) файлов MP4 и MP3. Определяется тип файла по содержимому, как при валидации загрузки.
- Локальный запуск Whisper, модель `base`. Внешние API не используются.
- Автоопределение языка речи.
- Статусы: «В очереди», «В процессе», «Готово», «Ошибка».
- Хранение в БД статуса, текста, времени завершения и текста ошибки.
- Последовательная очередь: одновременно обрабатывается один файл.
- Повторный запуск при перезапуске API для задач «В очереди» и «В процессе».
- API: статус и текст транскрибации, скачивание `.txt`, повторный запуск для статуса «Ошибка».
- Веб-интерфейс на странице встречи: бейдж статуса, периодический опрос API, пока есть незавершённая задача, показ текста, кнопка «Скачать .txt», кнопка «Повторить» при ошибке.
- Каскадное удаление: удаление файла или встречи отменяет задачу и удаляет результат.
- Сообщения об ошибках и интерфейс на русском языке.
- Тесты: unit и e2e на API, unit-тесты веб-компонентов.
- Обновление `CLAUDE.md` и `README.md` в той же правке: новые эндпоинты, переменные окружения, установка Whisper.

## Не в скоупе

- Другие модели Whisper (`tiny`, `small`, `medium`, `large`) и выбор модели пользователем.
- Транскрибация других форматов (MOV, WEBM, M4A, WAV).
- Выбор языка пользователем.
- Таймкоды, разметка по спикерам, субтитры (VTT/SRT), перевод.
- Показ процента прогресса.
- Real-time обновление статуса через WebSocket или SSE.
- Редактирование текста транскрибации.
- Поиск по тексту, краткое содержание, действия по итогам встречи.
- Отдельный сервис, внешняя очередь (Redis, RabbitMQ), распределённая обработка.
- Ручная отмена транскрибации кнопкой.
- Уведомления (email, push) о завершении.
- Запуск транскрибации для встреч, загруженных до выхода фичи.

## Технические ограничения

- Модель Whisper называется `base`. Названия «low» у Whisper нет, заказчик выбрал `base`.
- Whisper запускается локально на машине с API. Нужны установленные Whisper и `ffmpeg`. Способ установки описывается в документации, а не зашивается в код.
- Whisper запускается во внешнем процессе или контейнере, а не в потоке Node. Тяжёлая работа не должна блокировать обработку HTTP-запросов.
- На CPU распознавание модели `base` идёт со скоростью порядка реального времени или быстрее. Часовая запись может обрабатываться заметно дольше минуты. Статус «В процессе» должен корректно держаться всё это время.
- Лимит файла встречи — 500 МБ, квота пользователя — 5 ГБ. Видео MP4 нужно уметь обрабатывать, извлекая звук.
- Нужен максимальный срок обработки одного файла. По его истечении процесс прерывается, статус «Ошибка».
- У встречи может быть один файл. Транскрибация привязана к файлу встречи (`MeetingFile`) и живёт не дольше него.
- Встречи хранятся в памяти API (см. «Ловушки» в корневом `CLAUDE.md`). `MeetingFilesCleanupService` при старте удаляет записи и файлы без встречи. Задачи на перезапуске нужно подбирать после этой очистки, чтобы не запускать транскрибацию для удалённых файлов.
- Текст транскрибации персональные данные пользователя. Он доступен только владельцу встречи (те же `JwtAuthGuard` и `MeetingOwnerGuard`, что у файла). Чужая встреча — 404.
- Уже действующие лимиты запросов (`RATE_LIMIT`) распространяются на новые эндпоинты. Повторный запуск тоже ограничивается, чтобы нельзя было заспамить очередь.
- Колонки и миграции — через Prisma (`db:migrate`). Файл миграции коммитится.
- Текущий статус файла встречи (`status = UPLOADED`) не должен меняться по смыслу. Статус транскрибации — отдельное поле.

## Критерии готовности

- [ ] После `POST` или `PUT` MP4/MP3 файла `GET /meetings/:id/file` возвращает статус транскрибации «В очереди» (или более поздний).
- [ ] После загрузки файла другого формата (например, PDF) транскрибация не создаётся и интерфейс статус не показывает.
- [ ] Для тестового MP3 с речью статус доходит до «Готово», текст непустой и соответствует содержимому записи.
- [ ] Для тестового MP4 с речью статус доходит до «Готово», текст получен из звуковой дорожки.
- [ ] Используется модель `base`, вызовов внешних сетевых сервисов нет.
- [ ] Одновременно в статусе «В процессе» находится не больше одного файла. Остальные ждут в статусе «В очереди».
- [ ] Повреждённый MP3/MP4 или недоступный Whisper приводит к статусу «Ошибка» с русским сообщением. API при этом не падает.
- [ ] Превышение максимального срока обработки прерывает процесс и даёт статус «Ошибка».
- [ ] `POST /meetings/:id/file/transcription/retry` (или аналог) для статуса «Ошибка» ставит задачу в очередь заново. Для остальных статусов возвращает 409.
- [ ] Транскрибацию и скачивание `.txt` можно получить только у владельца встречи. Чужая или несуществующая встреча — 404, без токена — 401.
- [ ] Скачанный `.txt` — UTF-8, `Content-Disposition: attachment`, имя файла основано на имени исходного файла.
- [ ] После перезапуска API задачи «В очереди» и «В процессе» выполняются повторно. Задачи удалённых файлов не запускаются.
- [ ] Удаление файла или встречи удаляет транскрибацию. Идущая обработка прерывается, результат не записывается.
- [ ] Замена файла сбрасывает прежний результат и запускает новую транскрибацию. Результат старого файла не показывается для нового, даже если старая задача завершилась позже.
- [ ] На странице встречи статус виден без перезагрузки: после загрузки автоматически меняется до «Готово» или «Ошибка». Опрос API прекращается, когда задач в работе нет.
- [ ] В интерфейсе работают «Скачать .txt» и «Повторить». Все надписи и сообщения об ошибках на русском.
- [ ] Есть unit-тесты (очередь, смена статусов, обработка ошибок, веб-компоненты) и e2e-тесты API (запуск после загрузки, права доступа, повтор, удаление). Whisper в тестах подменяется.
- [ ] `pnpm lint`, `pnpm typecheck` и `pnpm test` проходят.
- [ ] `CLAUDE.md` (корневой, `apps/api`, `apps/web`) и `README.md` описывают новые эндпоинты, переменные окружения и установку Whisper/ffmpeg.
