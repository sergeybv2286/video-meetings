# PRD: Страница профиля и редактирование профиля пользователя

**Дата**: 2026-10-15
**Статус** Draft

## Цель

Дать пользователю страницу профиля и страницу её редактирования: изменить имя и email, загрузить или удалить аватар, сменить пароль (с вводом старого), удалить аккаунт. Аватар виден в профиле и в шапке главной страницы рядом с именем залогиненного пользователя, чтобы было понятно, под кем выполнен вход.

## Пользовательские сценарии

- Пользователь открывает страницу профиля -> видит аватар (или заглушку с инициалами), имя, email и кнопку «Редактировать»
- Пользователь без аватара открывает профиль -> видит круглую заглушку с инициалами имени (или email, если имя не задано)
- Пользователь нажимает «Редактировать» -> попадает на страницу редактирования с формами имени/email, аватара и пароля
- Пользователь меняет имя и сохраняет -> видит подтверждение, новое имя отображается в профиле и в шапке главной страницы
- Пользователь очищает имя и сохраняет -> имя сбрасывается, везде показывается email
- Пользователь меняет email на свободный -> email обновляется; на занятый -> сообщение об ошибке на русском (409), данные не меняются
- Пользователь выбирает изображение JPEG/PNG/WebP до 5 МБ -> аватар загружается, виден прогресс, затем показывается в профиле и в шапке главной страницы
- Пользователь выбирает файл недопустимого типа или больше 5 МБ -> получает понятное сообщение об ошибке, загрузка не начинается
- Загрузка аватара прервалась -> пользователь видит ошибку и может повторить; прежний аватар остаётся
- Пользователь загружает новый аватар поверх старого -> старый заменяется и удаляется с сервера
- Пользователь удаляет аватар (с подтверждением) -> возвращается заглушка с инициалами везде, файл удалён с сервера
- Пользователь вводит верный старый пароль и новый -> пароль меняется, показывается подтверждение
- Пользователь вводит неверный старый пароль -> получает ошибку на русском, пароль не меняется
- Пользователь вводит слишком короткий новый пароль -> получает ошибку валидации, пароль не меняется
- Пользователь нажимает «Удалить аккаунт» и вводит пароль -> после подтверждения аккаунт и аватар удалены, происходит выход на страницу входа
- Неавторизованный пользователь открывает профиль или редактирование -> перенаправляется на страницу входа

## В скоупе

- Страница профиля: аватар, имя, email, ссылка на редактирование.
- Страница редактирования профиля с отдельными блоками:
  - имя и email (используют существующие `PATCH /users/me`);
  - аватар: загрузка, замена, удаление;
  - смена пароля: старый пароль, новый пароль (существующий `PUT /users/me/password`);
  - удаление аккаунта с вводом пароля (существующий `DELETE /users/me`).
- Аватар:
  - форматы JPEG, PNG, WebP, максимум 5 МБ;
  - проверка типа и размера на клиенте (быстрая обратная связь) и на сервере (обязательно, тип — по содержимому файла);
  - один аватар на пользователя, хранится на сервере, метаданные/ссылка привязаны к пользователю;
  - отображается круглым без клиентского кадрирования (обрезка средствами CSS);
  - заглушка с инициалами, если аватара нет.
- Эндпоинты API для аватара: загрузка/замена, получение, удаление. Загрузку и удаление может выполнять только сам пользователь; получение — любой авторизованный пользователь.
- Поле «есть ли аватар» (или URL аватара) в профиле пользователя в ответах `/users/*`.
- Аватар и ссылка на профиль в шапке главной страницы рядом с именем залогиненного пользователя; обновляется сразу после изменений без повторного входа.
- Удаление файла аватара при удалении аккаунта.
- Сообщения интерфейса и ошибок API — на русском.
- Тесты (unit и e2e) для нового поведения.
- Обновление документации (`CLAUDE.md`, `README.md`, `.env.example` при новых переменных).

## Не в скоупе

- Клиентский редактор кадрирования, масштабирования и поворота аватара.
- Серверная обработка изображений (ресайз, генерация миниатюр, конвертация форматов).
- Анимированные и SVG-аватары.
- Показ аватаров в списке встреч, на странице встречи, в результатах поиска пользователей и в других местах, кроме профиля и шапки главной страницы.
- Просмотр профиля других пользователей.
- Подтверждение email, восстановление пароля, выход со всех устройств после смены пароля.
- Двухфакторная аутентификация, привязка соцсетей.
- Хранение файлов в облачном хранилище (S3 и т.п.).

## Технические ограничения

- Пользователи хранятся в Postgres через Prisma; изменения схемы — только через миграции в `apps/api/prisma/migrations`.
- Файлы лежат на диске сервера (как файлы встреч); каталог задаётся переменной окружения, новые переменные добавляются в `.env.example`.
- JWT хранит email на момент входа, поэтому после смены email `/auth/me` отдаёт старое значение до повторного входа; актуальные данные профиля берутся из `/users/me`, и интерфейс не должен показывать устаревший email/имя.
- Хеш пароля не отдаётся наружу (использовать `toProfile()` / `UserProfile`).
- Веб: Next.js App Router, HeroUI, Tailwind; интерфейс на русском, доступность форм (подписи, ошибки, фокус).
- Смена пароля не должна требовать повторного входа в текущей сессии.

## Критерии готовности

- [ ] Страница профиля показывает аватар (или инициалы), имя и email текущего пользователя
- [ ] Неавторизованный пользователь на страницах профиля и редактирования перенаправляется на вход
- [ ] Имя можно изменить и сбросить; изменения видны в профиле и в шапке главной страницы без повторного входа
- [ ] Email можно изменить; при занятом email возвращается 409 и показывается русское сообщение
- [ ] Аватар JPEG/PNG/WebP до 5 МБ загружается и отображается в профиле и в шапке главной страницы
- [ ] Файл другого типа (в том числе с подменённым расширением) или больше 5 МБ отклоняется на сервере с понятной ошибкой; на клиенте загрузка не начинается
- [ ] При замене аватара старый файл удаляется с диска; при сбое загрузки прежний аватар сохраняется
- [ ] Удаление аватара (с подтверждением) возвращает заглушку с инициалами и удаляет файл с диска
- [ ] Пароль меняется только при верном старом пароле; неверный старый или короткий новый пароль даёт ошибку, пароль не меняется
- [ ] После смены пароля вход со старым паролем невозможен, с новым — возможен
- [ ] Удаление аккаунта требует пароль, удаляет аватар с диска и выполняет выход
- [ ] Пользователь не может загрузить или удалить аватар другого пользователя
- [ ] Все сообщения интерфейса и ошибок API на русском
- [ ] Миграция БД применяется, e2e-тесты API и unit-тесты web/api проходят (`pnpm test`, `pnpm --filter api test:e2e`)
- [ ] `pnpm format`, `pnpm lint`, `pnpm typecheck` проходят без ошибок
- [ ] Документация (`CLAUDE.md`, `apps/*/CLAUDE.md`, `README.md`, `.env.example`) обновлена в той же правке
