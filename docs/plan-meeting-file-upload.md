# Plan: Загрузка файла встречи

**PRD:** docs/prd-meeting-file-upload.md
**Дата:** 2026-10-09

**Принятое решение по «осиротевшим» данным:** метаданные файла хранятся в Postgres (Prisma) без FK на встречу (встречи пока в памяти); при старте API удаляются файлы и записи, чьей встречи нет в памяти. Перенос встреч в БД — отдельная задача.

## Фазы реализации

### Фаза 1: Tracer Bullet — загрузка и информация о файле (API)

**Цель:** владелец встречи может загрузить файл через API и получить его метаданные; данные переживают перезапуск.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Prisma-модель `MeetingFile` (meetingId уникальный, исходное имя, MIME-тип, размер, дата загрузки, статус как enum с единственным значением `UPLOADED`, путь хранения) и миграция
- [ ] Переменная окружения с путём хранения файлов (`.env.example`), папка в `.gitignore`, конфигурация в API
- [ ] Модуль файлов встречи: `POST /meetings/:id/file` (multipart, потоковая запись на диск, имя на диске генерируется сервером) и `GET /meetings/:id/file` (метаданные); JWT, доступ только владельцу, 404 для чужой/несуществующей встречи, 401 без JWT
- [ ] Unit-тесты сервиса/обработчиков (сохранение метаданных, проверка владельца)
- [ ] e2e-тесты: успешная загрузка, получение метаданных, чужая/несуществующая встреча (404), без JWT (401)

**Когда готова:** через API можно загрузить допустимый файл в свою встречу и получить его метаданные со статусом «Загружен»; после перезапуска API файл и метаданные на месте; тесты фазы проходят.

### Фаза 2: Валидация и защита от «битых» файлов (API)

**Цель:** сервер отклоняет недопустимые файлы и не оставляет мусор при ошибках.
**Затрагивает:** backend
**Задачи:**

- [x] Лимит 500 МБ на сервере (лимит multipart, лимит тела запроса, таймауты) с русским сообщением об ошибке (413)
- [x] Проверка типа по содержимому/MIME (magic bytes) для mp4, webm, mov, mp3, m4a, wav, txt, vtt, srt, pdf, docx, pptx; переименованное расширение отклоняется с русским сообщением (415/400)
- [x] Защита от path traversal (исходное имя не влияет на путь) и очистка частично записанного файла и метаданных при обрыве/ошибке/отказе валидации
- [x] Unit-тесты валидатора типа и размера, очистки при ошибке
- [x] e2e-тесты: файл больше лимита, недопустимый тип, переименованное расширение, вредоносное имя файла, прерванная загрузка не оставляет файла на диске и записи в БД

**Когда готова:** все недопустимые загрузки отклоняются с понятным русским сообщением, на диске и в БД нет остатков; тесты фазы проходят.

### Фаза 3: Скачивание, замена и удаление (API)

**Цель:** полный жизненный цикл файла через API.
**Затрагивает:** backend
**Задачи:**

- [x] `GET /meetings/:id/file/download` — потоковая отдача с исходным именем и корректными заголовками
- [x] Замена: повторная загрузка в встречу с файлом (`PUT /meetings/:id/file`) сохраняет новый файл и удаляет старый с диска и из метаданных; при ошибке старый файл остаётся нетронутым
- [x] `DELETE /meetings/:id/file` — удаление с диска и из метаданных
- [x] Unit-тесты замены и удаления (включая откат при ошибке замены)
- [x] e2e-тесты: скачивание (совпадение контрольной суммы), замена (на диске только новый файл), удаление, 404 для чужой/несуществующей встречи и отсутствующего файла, 401 без JWT

**Когда готова:** файл можно скачать (контрольная сумма совпадает), заменить и удалить через API; тесты фазы проходят.

### Фаза 4: Индикатор файла в списке и очистка сирот (API)

**Цель:** список встреч показывает наличие файла; данные согласованы после перезапуска API.
**Затрагивает:** backend
**Задачи:**

- [ ] Поле «есть файл» в ответах `GET /meetings` и `GET /meetings/:id`
- [ ] Очистка при старте API: удаление записей `MeetingFile` и файлов на диске, у которых нет встречи в памяти, а также файлов на диске без записи в БД
- [ ] Unit-тесты очистки сирот и расчёта признака «есть файл»
- [ ] e2e-тесты: признак «есть файл» в списке и в деталях встречи; после удаления файла признак сбрасывается

**Когда готова:** `GET /meetings` возвращает признак наличия файла; после перезапуска API нет файлов и метаданных без встречи; тесты фазы проходят.

### Фаза 5: Интерфейс загрузки файла (web)

**Цель:** пользователь загружает файл на странице встречи и видит карточку файла.
**Затрагивает:** frontend
**Задачи:**

- [ ] Зона загрузки на странице встречи: выбор через диалог и drag-and-drop, подсказка о форматах и размере, управление с клавиатуры, адаптивность на мобильной ширине
- [ ] Клиентская проверка типа и размера (500 МБ) с русскими сообщениями об ошибках, загрузка не начинается при ошибке
- [ ] Загрузка напрямую в API (учёт разных origin/CORS) с индикатором прогресса, сообщением об ошибке и повтором
- [ ] Карточка файла: имя, тип, размер, дата загрузки, статус «Загружен»
- [ ] Тесты: unit-тесты клиентской валидации и форматирования; проверка сценариев (успех, недопустимый тип/размер, ошибка загрузки) в интерфейсе, в том числе через Playwright MCP

**Когда готова:** на странице своей встречи можно загрузить файл и увидеть карточку; ошибки показываются по-русски; интерфейс работает на мобильной ширине и с клавиатуры; тесты фазы проходят.

### Фаза 6: Скачивание, замена, удаление и индикатор в списке (web)

**Цель:** полное управление файлом из интерфейса.
**Затрагивает:** frontend
**Задачи:**

- [ ] Кнопка скачивания файла в карточке
- [ ] Замена файла (с прогрессом и обработкой ошибок, старый файл остаётся при сбое)
- [ ] Удаление файла с диалогом подтверждения; после удаления снова доступна зона загрузки
- [ ] Индикатор «есть файл» в списке встреч
- [ ] Тесты: unit-тесты компонентов/хуков и проверка сценариев скачивания, замены, удаления и индикатора в списке (в том числе через Playwright MCP, мобильная ширина, клавиатура)

**Когда готова:** из интерфейса можно скачать, заменить и удалить файл; в списке видно встречи с файлом; тесты фазы проходят.
