# Plan: Страница профиля и редактирование профиля пользователя

**PRD:** [docs/prd-user-profile-page.md](prd-user-profile-page.md)
**Дата**: 2026-10-15

## Фазы реализации

### Фаза 1: Профиль и редактирование имени/email (Tracer Bullet)

**Цель:** Минимальный рабочий путь от шапки главной страницы до сохранения данных: пользователь открывает профиль, редактирует имя и email и видит изменения. Используются только существующие эндпоинты API.
**Затрагивает:** frontend
**Задачи:**

- [ ] Страница профиля `/profile`: имя, email, заглушка с инициалами (имя или email, если имя не задано), кнопка «Редактировать»; данные из `GET /users/me`; редирект на вход для неавторизованных
- [ ] Страница `/profile/edit` с формой имени и email (`PATCH /users/me`): подтверждение успеха, очистка имени, ошибка 409 на русском для занятого email; редирект на вход для неавторизованных
- [ ] В шапке главной страницы: заглушка с инициалами и имя рядом, ссылка на профиль; данные обновляются после сохранения без повторного входа (учесть, что `/auth/me` отдаёт устаревший email)
- [ ] Тесты (vitest): функция инициалов, форма имени/email (успех, сброс имени, 409, ошибки валидации), редирект неавторизованного
- [ ] Обновить `apps/web/CLAUDE.md`, корневой `CLAUDE.md` («Текущее состояние») и `README.md`

**Когда готова:** Пользователь из шапки главной попадает в профиль, меняет имя/email, изменения видны в профиле и шапке без повторного входа; занятый email даёт русское сообщение; `pnpm test`, `pnpm lint`, `pnpm typecheck` проходят.

### Фаза 2: Смена пароля и удаление аккаунта

**Цель:** Завершить страницу редактирования блоками безопасности на существующих эндпоинтах.
**Затрагивает:** frontend
**Задачи:**

- [x] Блок смены пароля на `/profile/edit`: старый и новый пароль (`PUT /users/me/password`), подтверждение успеха, ошибки неверного старого и короткого нового пароля на русском, сессия сохраняется
- [x] Блок удаления аккаунта: кнопка, модальное подтверждение с вводом пароля (`DELETE /users/me`), при успехе выход и редирект на страницу входа, ошибка неверного пароля
- [x] Тесты (vitest): смена пароля (успех, неверный старый, короткий новый), удаление аккаунта (успех с выходом, неверный пароль)
- [x] Проверить e2e API: старый пароль не работает после смены, новый работает; удаление аккаунта требует пароль (добавить недостающие тесты в `apps/api/test/users.e2e-spec.ts`)
- [x] Обновить `apps/web/CLAUDE.md` и корневой `CLAUDE.md`

**Когда готова:** Пароль меняется только при верном старом; после смены вход со старым паролем невозможен, с новым возможен; удаление аккаунта требует пароль и выполняет выход; тесты проходят.

### Фаза 3: API аватара

**Цель:** Серверная часть аватара: хранение, валидация, эндпоинты и отдача признака аватара в профиле.
**Затрагивает:** backend / database
**Задачи:**

- [x] Миграция Prisma и модель аватара пользователя (привязка к пользователю, тип, размер, путь); переменная каталога хранения в `.env.example`
- [x] Эндпоинты загрузки/замены (`PUT /users/me/avatar`), получения (`GET /users/:id/avatar`, любой авторизованный) и удаления (`DELETE /users/me/avatar`); JPEG/PNG/WebP до 5 МБ, тип проверяется по содержимому; при замене старый файл удаляется, при сбое прежний сохраняется; русские сообщения об ошибках
- [x] Признак/URL аватара в ответах `/users/*` (`toProfile()`); удаление файла аватара при `DELETE /users/me`
- [x] Тесты: unit (валидация типа по содержимому, лимит размера) и e2e `apps/api/test/` (загрузка, замена и удаление файла с диска, подменённое расширение, >5 МБ, чужой аватар недоступен для изменения, удаление аккаунта чистит файл, 401 без токена)
- [x] Обновить `apps/api/CLAUDE.md`, корневой `CLAUDE.md`, `README.md`

**Когда готова:** Через API аватар загружается, заменяется, отдаётся и удаляется; недопустимые файлы отклоняются; файлы удаляются с диска при замене, удалении аватара и аккаунта; `pnpm test` и `pnpm --filter api test:e2e` проходят.

### Фаза 4: Аватар в интерфейсе

**Цель:** Пользователь управляет аватаром на странице редактирования и видит его в профиле и шапке главной страницы.
**Затрагивает:** frontend
**Задачи:**

- [ ] Компонент аватара: круглое изображение (CSS-обрезка) или заглушка с инициалами; использовать в профиле и в шапке главной страницы вместо заглушки из фазы 1
- [ ] Блок аватара на `/profile/edit`: выбор файла, клиентская проверка типа и размера (до 5 МБ), прогресс загрузки, ошибка с возможностью повтора, замена, удаление с подтверждением
- [ ] Обновление аватара в шапке и профиле сразу после загрузки/удаления без повторного входа
- [ ] Тесты (vitest): клиентская валидация типа и размера, загрузка (успех, ошибка с повтором), удаление с подтверждением, отображение аватара и заглушки
- [ ] Проверить интерфейс в браузере (Playwright MCP) и обновить `apps/web/CLAUDE.md`, корневой `CLAUDE.md` («Текущее состояние»), `README.md`

**Когда готова:** Загруженный аватар виден в профиле и шапке главной; недопустимый файл не отправляется; удаление возвращает инициалы; `pnpm format`, `pnpm lint`, `pnpm typecheck`, `pnpm test` проходят, документация сверена с кодом.
