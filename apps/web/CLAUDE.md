# apps/web — Next.js

Общие правила репозитория — в `../../CLAUDE.md`.

## Команды (из `apps/web` или `pnpm --filter web ...`)

- `dev` — порт 3000; `build`, `start`
- `lint` (ESLint + `eslint-config-prettier`), `lint:fix`
- `test` — unit-тесты (vitest, `src/**/*.test.{ts,tsx}`, конфиг `vitest.config.mts`, `setupFiles` подключает `@testing-library/jest-dom`); `test:watch`. Окружение всех тестов — jsdom (компоненты — `@testing-library/react` и `user-event`, `lib/api` мокается через `vi.mock('@/lib/api', …)`).
- `typecheck` — `tsc --noEmit`. Без предварительного `build`/`dev` может падать из-за отсутствия `.next/types`.

## Структура и соглашения

- App Router, исходники в `src/`, алиас `@/*` -> `src/*`.
- Страницы: `/` (защищена, создание встречи и единый список «Ваши встречи»; встречи — ссылки на `/meetings/<id>`), `/meetings/[id]` (защищена; заголовок и дата встречи, затем либо зона загрузки `FileUpload`, либо карточка файла `FileCard`; 404 от API — «Встреча не найдена»), `/login`, `/register`, `/profile` (защищена; аватар или заглушка с инициалами, имя или «Имя не указано», email, кнопка «Редактировать»; данные из `GET /users/me`), `/profile/edit` (защищена; четыре карточки: фото профиля, форма имени и email, смена пароля, удаление аккаунта).
- Профиль: `src/components/change-password-form.tsx` — смена пароля (`PUT /users/me/password` через `api.changePassword`; новый пароль короче 6 символов не отправляется, сообщение на русском; ошибка сервера, например «Неверный текущий пароль», показывается под полями; при успехе сервер отзывает старые токены и возвращает новый — `saveSession` заменяет им сессию, поля очищаются, «Пароль изменён»); `src/components/delete-account-section.tsx` — удаление аккаунта (`DELETE /users/me` через `api.deleteAccount`; `AlertDialog` с вводом пароля, кнопка подтверждения неактивна без пароля; при неверном пароле диалог остаётся открытым с ошибкой; при успехе `clearSession()` и `router.replace('/login')`). `src/lib/initials.ts` — `getInitials(name, email)` (до двух слов имени, без имени — первая буква email); `src/components/avatar-placeholder.tsx` — круглая заглушка с инициалами (`size` `md` в шапке, `lg` в профиле); `src/components/avatar.tsx` — круглый аватар: при `hasAvatar` грузит изображение через `api.getAvatar` (fetch с JWT → blob → `URL.createObjectURL`, освобождается при смене и размонтировании; перезагрузка при смене `avatarUpdatedAt`), без аватара, пока грузится и при ошибке показывает `AvatarPlaceholder`; `src/components/avatar-section.tsx` — блок фото на `/profile/edit` (кнопки «Загрузить фото»/«Заменить фото» со скрытым `<input type=file>`; клиентская проверка JPEG/PNG/WebP до 5 МБ в `src/lib/avatar-file.ts` должна совпадать с серверной; прогресс и «Отменить»; ошибка с «Повторить загрузку»; «Удалить фото» с подтверждением в `AlertDialog`, 404 при удалении считается успехом; загрузка — `uploadAvatar` на XHR, удаление — `api.deleteAvatar`; после успеха вызывает `onChanged` с обновлённым профилем); `src/components/user-badge.tsx` — блок в шапке главной (аватар или заглушка, имя, email, ссылка на `/profile`; email и имя берутся из `GET /users/me`, пока он грузится — email из сессии); `src/components/profile-form.tsx` — форма имени и email (`PATCH /users/me` через `api.updateMe`; пустое имя сбрасывает имя; при изменении email появляется обязательное поле «Текущий пароль (для смены email)», пароль уходит только вместе с изменённым email; 409 показывается как «Этот email уже занят»; подтверждение «Изменения сохранены» скрывается при следующей правке). После сохранения страница `/profile/edit` обновляет email в сессии (`saveSession`), чтобы email в сессии не расходился с профилем; главная при монтировании запрашивает профиль заново.
- Файл встречи: `src/lib/meeting-file.ts` — клиентская проверка (допустимые расширения и лимит 500 МБ должны совпадать с серверными в `apps/api/src/meeting-files/meeting-file.types.ts`; сообщения на русском; при ошибке загрузка не начинается), `formatFileSize`, `fileTypeLabel`. Компоненты: `file-upload.tsx` — зона загрузки (кнопка «Выбрать файл» со скрытым `<input type=file accept>`, drag-and-drop, прогресс, «Отменить», ошибка с «Повторить загрузку»; props `method` `POST`/`PUT`, `heading`, `onCancel`; после обрыва сети или 409 перепроверяет файл на сервере и показывает карточку, если он сохранился); `file-card.tsx` — карточка (имя, тип, размер, дата, статус «Загружен», слот `actions`); `file-section.tsx` — карточка с действиями: «Скачать», «Заменить файл» (открывает `FileUpload` с `PUT`; при сбое старая карточка и файл не меняются), «Удалить» (`AlertDialog` с подтверждением: Escape/«Отмена» закрывают, пока идёт удаление диалог заблокирован, ошибка видна в диалоге, 404 при удалении считается успехом). Страница встречи после удаления показывает `FileUpload`. В списке встреч у встреч с файлом метка «Есть файл» (`hasFile` из API). API-слой (`lib/api.ts`): загрузка и замена — `uploadMeetingFile` на XMLHttpRequest (только он даёт прогресс отправки; CORS разрешает origin из `WEB_ORIGIN`), скачивание — `downloadMeetingFile` (fetch с JWT → blob → ссылка `download`; имя берётся из метаданных, поэтому `Content-Disposition` в CORS не нужен; файл целиком держится в памяти браузера), удаление — `api.deleteMeetingFile` (204 без тела).
- Транскрибация (`src/components/transcription-section.tsx`, под `FileSection` на `/meetings/[id]`): секция видна, только если у файла `transcriptionStatus` не `null` (MP4/MP3). Бейдж статуса («В очереди», «В процессе», «Готово», «Ошибка»), текст при «Готово», сообщение сервера и «Повторить» при «Ошибка», «Скачать .txt» (`downloadTranscription` в `api.ts`, имя — исходное без расширения + `.txt`). Пока статус «В очереди»/«В процессе», раз в `POLL_INTERVAL_MS` (3 с) опрашивается `api.getTranscription`; на «Готово»/«Ошибка» опрос останавливается, при сбое сети опрос задачи в работе продолжается, а кнопка «Обновить» перезапускает его вручную. Страница задаёт `key` = `id:uploadedAt` файла, поэтому замена файла сбрасывает состояние и опрос, а удаление размонтирует секцию. Тесты — `transcription-section.test.tsx` (фейковые таймеры).
- Заголовки безопасности (CSP, `X-Frame-Options`, `Referrer-Policy` и др.) задаются в `next.config.ts` (`headers()`); CSP пропускает только свой origin и `NEXT_PUBLIC_API_URL`, при смене адреса API она подхватывается автоматически. Скрипты — с `'unsafe-inline'` (нужен гидратации Next и скрипту темы), строгая CSP с nonce потребовала бы динамического рендера всех страниц. Токен по-прежнему в `localStorage` — защита от XSS держится на CSP.
- `src/components/theme-toggle.tsx` — кнопка переключения темы (фиксирована в правом верхнем углу, подключена в `layout.tsx`).
- `src/components/app-title.tsx` — градиентный заголовок «Video Meetings» (на главной и в форме входа/регистрации).
- `src/lib/api.ts` — единственная точка обращения к API (`NEXT_PUBLIC_API_URL`, по умолчанию `http://localhost:3001`). Подставляет `Authorization: Bearer`, при 401 сбрасывает сессию.
- `src/lib/session.ts` — сессия (токен и email) в `localStorage` под ключом `vm.session` (email обновляется после смены в профиле), хук `useSession()` через `useSyncExternalStore`. `loading: true`, пока клиент не прочитал хранилище.
- Защита страниц сейчас клиентская: при `!loading && !session` делается `router.replace('/login')`.
- Правила `react-hooks` строгие: не вызывайте `setState` синхронно в `useEffect`, не оборачивайте в `useCallback`/`useMemo` не инлайн-функции.
- Интерфейс на русском (`<html lang="ru">`), стили на Tailwind v4 и HeroUI v3 (`@heroui/react`, `@heroui/styles`, подключены в `src/app/globals.css` после `tailwindcss`). Провайдер не нужен, компоненты составные (`Card.Header`), вместо `onClick` — `onPress`. Цвета берите из токенов HeroUI (`bg-background`, `text-foreground`, `text-danger`). Тёмная тема HeroUI включается классом `dark` на `<html>`: inline-скрипт в `layout.tsx` ставит её до гидратации (выбор из `localStorage` `vm.theme` или `prefers-color-scheme`), переключает `src/components/theme-toggle.tsx`.
- UI-правила: на всех страницах только компоненты HeroUI; у полей видимый `Label`; интерактивные элементы не ниже 44px (`min-h-11`); вторичный текст — `text-muted` (не `opacity-*`); при загрузке — `Skeleton`, при отправке — `isPending`; анимации отключаются при `prefers-reduced-motion` (`globals.css`).
- **При любом изменении UI обязательно проверяйте результат визуально и по скиллу `ui-ux-pro-max`.** Запустите приложение (`pnpm dev`), откройте затронутые страницы через MCP `playwright` (скриншоты, светлая и тёмная темы, мобильная ширина, клавиатурная навигация и состояния: загрузка, ошибка, пусто) и убедитесь, что изменения работают как задумано. Затем сверьте UI с правилами скилла `ui-ux-pro-max` (доступность, касания, контраст, формы, адаптивность, анимации — см. `.claude/skills/ui-ux-pro-max/references/`) и исправьте найденные замечания до завершения задачи. Проверка только по коду без просмотра в браузере недостаточна.
- Переменные окружения описывайте в `.env.example`.
